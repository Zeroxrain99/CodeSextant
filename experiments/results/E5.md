# E5: replacing ROSE's silence with a ranked answer

`docs/audit.md` found that E2's null was decided before the first agent ran: `preflight`
named 8% of the companion files those tasks turned on, against 67% the agents found
unaided, and its co-change section printed *"History shows nothing that reliably changes
with this file"* in 9 of the 20 tasks. This is the fix for that half, and the measurement
of it.

**What was implemented is a known remedy for a known defect, not an idea.** What this
project shipped is ROSE (Zimmermann et al.): pairwise association rules thresholded at
`support >= 3` and `confidence >= 0.5`. Its documented limit is answering about a quarter
of the time. TARMAQ (Rolfsnes, Di Alesio, Behjati, Moonen, Binkley — SANER 2016) exists to
fix exactly that: rank rather than threshold, degrade to the largest matching subset of the
query, and be applicable 100% of the time. `cochange.rank_companions` is that algorithm
with `k` pinned to 1 — the storage keeps per-file and per-pair counts rather than the
transactions, which is what makes the index incremental, and at `k = 1` the two agree.
Ranking is by a Wilson lower bound on confidence, so one-of-one scores 0.21 against
nineteen-of-twenty at 0.76 and thin evidence sorts down instead of silencing the answer.

## The arms, and the choice fixed before the held-out repository was read

`cochange` is the shipped threshold. `ranked@N` replaces it outright. `hybrid@N` keeps the
threshold wherever it fires and ranks only where it does not. `topup@N` starts from the
threshold and fills the budget from the ranking. Every arm has a matched-budget
`frequency@N` control, because a predictor that names more files finds more companions for
reasons that have nothing to do with what it knows.

**The rule, stated before vite was run: take the arm that wins on the most derivation
repositories without losing on any.** `ranked@5` and `topup@5` each won on four and lost
on express. `hybrid@5` won on all five, so `hybrid@5` is the arm.

| derivation | `cochange` F1 | `hybrid@5` F1 | paired ΔF1 | recall | speaks |
|---|---|---|---|---|---|
| requests | 0.158 | **0.250** | −0.091 [−0.110, −0.072] | 0.093 → 0.200 | 0.47 → 0.91 |
| click | 0.177 | **0.239** | −0.062 [−0.077, −0.048] | 0.105 → 0.191 | 0.52 → 0.94 |
| tqdm | 0.141 | **0.233** | −0.091 [−0.108, −0.076] | 0.082 → 0.197 | 0.48 → 0.93 |
| express | 0.339 | **0.357** | −0.017 [−0.028, −0.006] | 0.220 → 0.265 | 0.81 → 0.94 |
| zod | 0.188 | **0.246** | −0.057 [−0.068, −0.046] | 0.111 → 0.177 | 0.54 → 0.84 |

(A negative Δ means the hybrid is better. Every interval excludes zero.)

## The held-out repository does not confirm it

| held out | precision | recall | F1 | paired ΔF1 |
|---|---|---|---|---|
| vite — `cochange` | **0.809** | 0.387 | **0.524** | |
| vite — `hybrid@5` | 0.683 | **0.414** | 0.516 | **+0.008 [+0.002, +0.014]** |

**The sign is positive and the interval excludes zero, which means the shipped threshold
is better on vite.** By 1.5% of its F1, against gains of 40-60% relative on the five
derivation repositories — but better, and this is the repository that was held back
precisely so that it could say so.

`hybrid@3` scores 0.522 on vite with a paired interval of [−0.002, +0.006], which is a
tie, and it also wins on all five derivation repositories. **It is not selected.** Reading
the held-out result and then choosing the arm that survives it is fitting to the held-out
set, and it would leave this change with no honest confirmation at all. Settling `N`
requires a repository nobody has looked at yet.

## What this does to the number the audit said was decisive

On E2's own twenty tasks, re-running `preflight` against the same indexes:

| | companions named | co-change spoke |
|---|---|---|
| before | 4 / 60 (7%) | 11 / 20 |
| after | **10 / 60 (17%)** | **19 / 20** |
| the agents, unaided | 40 / 60 (67%) | — |

*(The audit's figure is 5/60 because it counted a companion named anywhere in
`preflight`'s output, including the blast radius. This counts the co-change list alone,
which is the part that changed.)*

**2.4× the recall, and still a quarter of what the agents manage on their own.** The tasks
that dominate the shortfall are unchanged: `alembic@b19ac41f19` 0 of 9, `flask@165af0a090`
0 of 9, `flask@8285adf5a4` 0 of 8 — the chore commits whose companions are CI and
dependency configuration, which is 43% of the answer set and which no history-only model
addresses. That was the audit's diagnosis and this measurement confirms it rather than
disturbing it.

## Two claims, with different amounts of evidence behind them

**"This raises co-change F1" is not established.** Five derivation repositories say yes and
the held-out repository says no. That is what a held-out set is for and it is reported as
what it is.

**"This replaces silence with ranked candidates" is established on all six.** Speak rate
goes from 0.47-0.81 to 0.84-0.94, and recall rises on every repository including vite. The
cost is precision, and it is disclosed rather than hidden: the payload carries
`co_change_ranked`, and the note says these are ranked rather than filtered and are
candidates rather than obligations.

**It ships on, at `N = 5`, and that is a judgement rather than a finding.** The reasoning:
the thing being replaced is an empty answer, which E2 showed to be the state that made this
tool useless; recall rises everywhere; and the precision cost is labelled where a reader
sees it. `CODESEXTANT_COCHANGE_RANKED_DISABLED=1` restores the previous behaviour exactly,
for anyone who weights precision above recall — which the vite result says is a defensible
position.

**What it does not do is make an agent experiment worth re-running.** 17% is movement, not
a different regime. The audit's own threshold for that was whether the number moves enough
to change what an agent could do with it, and a tool that names one companion in six, where
the agent already names four in six, is not that.
