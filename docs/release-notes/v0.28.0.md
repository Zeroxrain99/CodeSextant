The release that makes CodeSextant the tool its README describes.

The last published version was **0.19.2**, which has neither `preflight` nor `check` nor
`guards` — the three commands the documentation is about. Everything below has been
sitting unreleased.

## Install

No PyPI upload in this release. Take the wheel from the assets below:

```bash
pip install https://github.com/Zeroxrain99/CodeSextant/releases/download/v0.28.0/codesextant-0.28.0-py3-none-any.whl
codesextant index .
```

For agents: `claude mcp add codesextant -- codesextant mcp` — ten tools over stdio, no
additional dependency.

## Three commands, one set of questions

CodeSextant exists for three failures that keep happening despite there being a query for
each: rebuilding something that already existed, forgetting the test or the allowlist or
the safety valve, and changing A while B quietly depended on it.

**`preflight`** asks before an edit, from a name and an intention. **`check`** asks after
it, from the diff, which carries evidence rather than intent — a body to compare shapes
against, the exact files touched, the exact symbols changed. It takes no arguments.

**`guards` is new.** `check` tells you *which file* your change forgot. `guards` tells you
*which fence, what it checks, and what would satisfy it*:

```
Guards: 5 in reach of this change

  TEST         test_an_unknown_format_is_refused_rather_than_guessed   tests/test_limits.py:4
    checks   1 assertion, first: "SUPPORTED_FORMATS" in str(exc)
    because  A silent fallback shipped bad data once; the allowlist is the fence.  (docstring)
    reached  names encode

  ALLOWLIST    SUPPORTED_FORMATS   pkg/limits.py:4
    checks   SUPPORTED_FORMATS admits 3: 'json', 'csv', 'ndjson'
    reached  you changed this file
```

It leads with a rule derived from the code rather than with prose, because a survey of
seven repositories found the author's reason absent for four guards in five — tests are
3% documented in one corpus repository, and thresholds and environment switches sit at or
near zero almost everywhere. The commit that introduced them does not carry the reason
either (0.00–0.04). A registry whose middle layer is prose would be empty for exactly the
fences that block people.

**And it is measured, on 360 real commits.** Hold out a file the commit had to touch that
holds a fence, apply the rest, and ask `guards` what the change is about to meet: it names
the held-out file in **0.306 of cases held out** while printing under five fences, beating
all four matched controls — the per-file design it replaced by +0.189, reading co-change
history instead by +0.156, the directories you touched by +0.139, the project's most-changed
files by +0.128, every interval excluding zero.

Four tiers of evidence, strongest first, and the last two exist because measurement
overruled the design. `guards` originally reached a fence only through the fence's own
text — you edited its file, or it spells a symbol you changed. Two tiers resting on a claim
about the *file* were written down as refused; both were then scored, and both reversed the
refusal, together worth +0.100 held out. They rank below every fence read off its own text
and say which claim they rest on, so a lead never reads as a hit.

## What is measured, and what is not

`experiments/` holds thirteen controlled experiments run against repositories nobody here
wrote, with control groups, bootstrapped intervals and a held-out set that was cloned
before the rules tested on it were written.

- Holding one file out of 351 real commits and asking `check` what the change forgot:
  recall **0.326 held out**, **+0.15 to +0.18** over the strongest matched control, every
  interval excluding zero, while naming under three files.
- Module-level dependents beat resolved callers in **all six repositories**.
- Co-change is **1.4× to 2.1×** more precise than the strongest control at a matched
  budget — on two of three repositories, which is the honest score.

**Where `guards` loses.** On jinja it is last, beaten by simply reading the project's
most-changed files by 0.167. A template engine drives its subjects through indirection, so
its tests never spell the names a per-guard rule matches on — and the same repository is
where the resolved-reference result reverses, for the same reason. Five repositories say
the rule is right and one says it is wrong, and nothing measured here predicts which case
a new repository is.

**And what none of it establishes.** Every number above measures *retrieval*: given a
query, is the right thing returned. Nothing here measures whether someone who saw the
answer made a better change or spent less fixing it — that is the prevention experiment,
and it is the one thing that would answer the question this tool exists for. The results
section lists what the experiments fail to show as carefully as what they show, because a
section that only lists wins is an advertisement.

## Also in this release

- **Windows was broken and is fixed.** `signal.SIGKILL` does not exist there, so every
  route-worker failure raised `AttributeError` out of the handler meant to return a
  retryable 503. `tests/test_portability.py` now walks the whole repository's AST and
  fails on any platform-only or version-gated name used as though it were universal.
- **Python 3.10 was broken and is fixed** — an unguarded `tomllib` import in the test
  suite.
- CI is green on 3 operating systems × 4 Pythons, plus packaging and a lint job holding a
  zero baseline.
