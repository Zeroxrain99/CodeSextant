A bug-fix release, from a report: another agent used CodeSextant for impact analysis,
hit a timeout, and fell back to grep. Reproducing that found two faults and neither was
the one in the report.

## Install

```bash
pip install https://github.com/Zeroxrain99/CodeSextant/releases/download/v0.29.0/codesextant-0.29.0-py3-none-any.whl
```

## A first call no longer fails

`preflight`, `check`, `code_map` and three others raised `RuntimeError` when a project
had never been indexed, and the daemon turns an exception into **HTTP 500**. Measured on
a clean home: `status` succeeded, then `preflight` returned a 500. An agent cannot act on
a 500 — it reads as the tool being broken, and nothing in it says that one `index` call
was the entire fix.

**The workaround made it worse on large repositories.** The MCP layer caught that error,
ran a full reindex on the 900-second heavy budget, then retried. So a first call against
a big repo blocked silently for minutes and whichever tool timeout was shortest fired
first. That is the reported timeout: not a hang, a silent index nobody was told about.

A first call now indexes the project itself when that is affordable and says so, and
otherwise returns immediately with a note telling you to run `index`. "Affordable" is 400
files, measured rather than picked: indexing runs at 55–289 files/sec across the corpus,
so 400 at the slowest observed rate is about eight seconds and leaves the query room
inside the budget. `CODESEXTANT_AUTOINDEX_MAX_FILES` moves it.

Cold `preflight` through the daemon: **500 → ok in 1.08 s**.

The interactive budget goes 15 s to 30 s, because a first call may now index inline.

## PineScript

A Pine project used to index to zero symbols, so every question came back empty — and an
empty answer is indistinguishable from "this tool cannot read your language" unless
something says so.

`tree_sitter_language_pack` ships 371 grammars and not this one, so PineScript is read
line by line. That is a weaker instrument and it is labelled as one: a grammar knows a
`=>` inside a string is not a function, and this knows it only because strings are
stripped first.

It reads `f(a) =>` and `export f(a) =>`, `method m(Type this) =>` scoped to the type it
extends, `type` and `enum` with their fields and members, and top-level variables
including `var`/`varip` and inputs.

On a three-file Pine repository: 3 files, 11 symbols, no errors, and `references` locates
a call site across files in 0.18 s.

## And an answer that was quietly misleading

`impact` builds its chain from resolved reference edges and, finding none, advised running
`find_references` to accumulate some. For a language with no import resolver that loop
cannot terminate — name matching never produces a high-confidence edge. So it sent Pine,
Go, Rust, Java and eight other languages round a loop that could not close, while an empty
chain read as "nothing depends on this" when it meant "nobody can tell you".

It now names the missing resolver, points at `references` instead, and says which of those
two an empty answer is.

## Unchanged

Everything measured in 0.28.0 still holds; nothing in this release touches a ranking or a
