- **裁決態：接受（MAJOR must-fix，含唯讀身分文字對齊）**。
- **理由**：storage.py 親驗只寫 `~/.codesextant/*.db`、從不寫目標 repo；草案 §4.3 `--update-baseline` 寫 `.codesextant/baseline.json` 到目標 repo = 史上第一個寫目標 repo 通道。唯讀鐵律精確語義 = **daemon 查詢路徑唯讀**，但「`--update-baseline` 是顯式 user 動作非 daemon 自動」的辯護**偷換了「工具不寫盤」這層**，須誠實重述非辯護。且 baseline.json 凍存量會 drift（過期→誤放行/誤報）= user 痛點「.md drift」搬到 baseline。

#### 【MUST-FIX-7】name-match 低信心邊接星圖標黃線 = 視覺紅燈弱化版（守鐵律2於視覺層）

## 一、最終設計（追溯用戶期許，具體到欄位/檔案）

### 1.0 一句話架構（含強制分層，吸收所有 must-fix）

```
TS 寫 spec（撰寫面，享 tsc+Zod 型別安全）  ←─[可選]  YAML IR 直寫（純非 TS repo 零 node 撰寫面）
   ↓ tsc + Zod.parse（spec 自身正確；寫不出非法規範）
spec.json 中性 IR（語言無關，帶 source_hash 防手改漂移）
   ↓ csx-conform 唯讀檢查引擎（站 symbols/references/import_edges 肩上；UNKNOWN 安全閘照抄 deadcode）
violations[]（每條帶 confidence:high|low|unknown + engine + rule_id）
   ├─→ daemon /conformance（永遠 SOFT/回 200/不 deny）→ 星圖獨立 conformance 著色層（high 紅實線 / low 灰點線 toggle）
   └─→ csx-conform CLI（顯式 user 跑）→ SARIF 2.1.0 + exit code
                                            ↓ user 顯式接進 CI run step
                                     CI exit≠0（HARD，唯一真強制）
```

**強制力分層（嚴守繼承①②③④⑤、身分鐵律4、L6 天花板）**：daemon 本體永遠 SOFT；真強制 = user 顯式把 `csx-conform` SARIF/exit code 接進 CI。CodeSextant 自己不 deny、不做 hook（grep model_capability/hooks=0 的能力分級天花板亦繼承——能力分級只 advisory）。

### 1.1 規範定義語言（核心問題①定案）

**雙層 + 雙撰寫面（吸收 MUST-FIX-8）**：

- **撰寫面 A（TS typed config，TS repo 用戶可選增強）**：dependency-cruiser `.ts` 範式 + Zod schema + `keyof typeof layers` 約束 `from`/`to` 只能引用已定義層名（寫錯 layer 名 tsc 報錯——user「寫錯編不過」在 spec 自身結構層的真兌現範圍）。
- **撰寫面 B（YAML IR 直寫，純非 TS repo 零 node）**：ast-grep/deptrac 範式，避免純 Go/Rust repo 為一條分層規則裝整套 node/npm/tsc。
- **機器面（中性 spec.json IR）**：兩撰寫面皆編譯/解析成同一 IR，帶 `source_hash`，引擎讀前校驗（stale 拒跑）。

**IR 規則類型（contract 分類學，借 import-linter）**：`forbid`（A 層禁 import B 層，具名非全域）/ `layers`（高→低單向）/ `naming`（symbols name regex）/ `orphan`（namegraph 孤兒，low advisory）/ `fanout`（出邊上限）。

**RegExp/glob 跨 JSON 邊界契約**（MUST-FIX-8 處方）：RegExp 序列化 `{source,flags}`、glob 用 minimatch 子集 + golden test 雙端比對。

**⚠ TS「編譯器強制」概念邊界誠實聲明（吸收 TS R1/R2，必寫進文檔/輸出）**：
- tsc/Zod **只強制 spec 檔案自身結構正確**（寫不出非法規範）。
- 「TS spec 對 TS repo」與「TS spec 對非 TS repo」在**編譯器是否參與強制上完全一樣=都不參與**，差別僅解析信心（TS=ts-morph high、非 TS=降級）。⛔刪草案「TS repo 最接近 user 期待」貼金（TS 編譯器不會因被檢業務 repo 違反 spec 而編不過——type graph 不含被檢 repo 原始碼）。
- 「寫錯編不過」在**任何被檢 repo 都變成「寫錯 CI 紅燈」**，非編譯前置強制——此為跨語言物理天花板（Wasp 編譯器強制是同生態 compiler），須向 user 揭露（→ §六 HUMAN-3）。

### 1.2 檢查引擎（核心問題②定案）

**規範類型 × 既有模組支撐性矩陣（吸收 MUST-FIX-1/3/6，移除未驗 ✅）**：

| 規範類型 | 站哪個模組 | 跨語言信心 | 可進 CI? | 新增成本 |
|---|---|---|---|---|
| 命名慣例 | symbols.py（16 語言 high） | 全 16 語言 high | **候選 [gated by P0-C]** | 零 |
| 分層存在/檔案放置 | symbols.py + path glob + **tag-based** | 全 16 語言 high | **候選 [gated by P0-C]** | 低 |
| 孤兒/未接線 | namegraph.compute_external_usage | 全 16 語言 **low** | ❌ 只 advisory（in-memory 重算） | 零 |
| 扇出上限 | import_edges 出邊數 | jedi/ts-morph high、其餘 low | 4 族 ✅、其餘 ❌ | 中 |
| 依賴方向 | **新增 import_edges 抽取層** | jedi/ts-morph high、14 語言 **NOT-AVAILABLE/unknown** | 僅 4 族 ✅ | **高（最大缺口，MUST-FIX-1）** |
| 母版/single-source | clones.py（結構級線索） | winnowing | ❌ 只 advisory（不宣稱語義強制） | 低 |

**import_edges 抽取層（MUST-FIX-1/2 定案）**：
- 新表 `import_edges(src_path, dst_path, confidence, resolver, line)`（SCHEMA 3→4，循 storage.py:147-159 冪等遷移）。
- **填充時機**：`csx-conform` 入口第一步主動全量抽取（不依賴 refs persist）。
- per-language dispatch：Python→jedi import 解析（high）、TS/JS→ts-morph `getImportDeclarations`（high）、**14 語言→邏輯模組路徑字串無磁碟檔解析能力 → `resolver=none`/`confidence=unknown`/標 NOT-AVAILABLE**（吸收跨語言 R1：不偽裝 `tree-sitter-textual` 有向邊；若 user 要 14 語言依賴方向須先過 PoC 量化「邏輯路徑→磁碟檔」可解析率）。

**UNKNOWN 安全閘（照抄 deadcode.py:348-389 黃金範本，MUST-FIX-3/7）**：非 jedi/ts-morph→UNKNOWN_NO_RESOLVER→SARIF note；真解析未定位→UNKNOWN_UNRESOLVED→note；唯「VIOLATION + high + crosses forbidden boundary」→error。`conformance_violations` 表 `assert confidence=='high'` 才落盤。

### 1.3 接回星圖（核心問題③定案）

**獨立 conformance 維度，不併 health（MUST-FIX-7）**：health 聚合「客觀腐化」，規範違反是「違反人定規則」語意不同。
- 新表 `conformance_violations(rule_id, path, line, symbol, severity, confidence, verdict, evidence)`，硬約束只存 high。
- 星圖獨立著色層（toggle）：high VIOLATION→節點紅 + 違規邊紅實線；low/UNKNOWN→**預設不畫**，顯式 toggle 才灰點線 + hover 警語，絕不與 high 同語彙。
- daemon 新端點 `/conformance`（daemon.py:413-434 `_ROUTES_GET` 塞一筆 OCP）→ 全回 200 JSON，三態（符合/無 spec→提示 `--init`/解析失敗）。
- 輸出沿用 engine.py:945-949「線索非決策」四件套（verdict+reason+verification_reminder+read_code_advisory），永不出「必須改」。

### 1.4 CI exit≠0 強制路徑 + 輸出格式（核心問題④定案）

**獨立 CLI `csx-conform`（不在 daemon 內，守鐵律4）**：

```bash
csx-conform --spec codesextant.spec.json --repo . \
  --baseline .codesextant/baseline.json \
  --changed-files-from git --format sarif --output results.sarif \
  --fail-on error
```

**exit code**：`0`=無 error 級 high VIOLATION（UNKNOWN/note/warn 不影響）；`1`=changed-files 內新增 error 級 high VIOLATION；`2`=spec 解析/IR/source_hash 校驗失敗。

**SARIF 2.1.0 level 映射（守 UNKNOWN 安全閘）**：

| verdict + confidence | SARIF level |
|---|---|
| VIOLATION + high + severity=error | `error` |
| VIOLATION + high + severity=warn | `warning` |
| 任何 UNKNOWN_* / low / 14 語言 fallback | **`note`**（⛔絕不 error） |
| RULE_MATCHED_ZERO_FILES | **不進被檢 repo 常駐 SARIF**（spec-lint 子模式報 / stderr summary） |

**`--summary-comment`（吸收唯讀 R6/no-op 可見性）**：把 note 級違規彙整成 PR 評論（可見不擋、守線索非決策），讓 14 語言 advisory 不在 CI 隱形。
**baseline + changed-files 增量**：MUST-FIX-5 定案（CI wrapper 落盤 + freshness hash + partialFingerprints 抗重構）。

### 1.5 跟 dependency-cruiser 的關係（核心問題⑤定案）：補強非取代

| 場景 | 用誰 | 理由 |
|---|---|---|
| JS/TS 依賴方向（W 維 HARD） | **dependency-cruiser 具名 forbid + CI 增量**（SSOT F2 欽定，⛔禁復活全域閘） | 成熟、JS/TS high、繼承結論④ |
| 非 JS/TS（Python/Rust/C#/Go…）W/I 維 | **CodeSextant 跨語言**（獨家賣點窄定位） | 填業界空白 |

### 1.6 定位邊界（核心問題⑥定案）：守架構/結構級
