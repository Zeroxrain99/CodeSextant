**關鍵技術定論（B agent 親讀坐實）**：jedi 對「規範符合度檢查（import-edge）」**零損失**——import 語句語法層寫死模組路徑、無同名歧義，tree-sitter 抽就達 high 信心；jedi 的 0% vs 99% 優勢只用在「符號級 find_references」（既有 map/refs/impact）。故失 jedi 只影響「分析 Python repo 的既有符號級導航」，靠 Python 配件補回。

## 一、目標架構：TS 核心 + 語言精度配件

```
┌─────────────────────────────────────────────────────────┐
│  codesextant（npm 套件，純 TS，一個 npm install -g）       │
│  ┌──────────────────────────────────────────────────┐   │
│  │ 核心引擎（全 TS、跨 16 語言、零綁其他 runtime）      │   │

│  │  ranking(PageRank) / clones(winnowing) / complexity│   │
│  │  health / deadcode(spawn ruff/eslint) / comments   │   │

│  │              name-match[其餘 low] + UNKNOWN 安全閘） │   │
│  │  🆕 import-edges（跨語言抽 import 語句+路徑resolution）│   │

│            ↓ 偵測有裝配件就 shell out 升 high              │
│  ┌──────────────────────────────────────────────────┐   │
│  │ 可選語言精度配件（optional，額外下載）              │   │
│  │  codesextant-python（jedi 子進程橋，Python repo     │   │
│  │    符號級 find_references/impact 升 high）          │   │

```

**配件契約（沿用既有 UNKNOWN 安全閘哲學）**：核心對非 JS/TS repo 預設 name-match（low/UNKNOWN、永不誤報紅燈）；偵測到對應語言配件已安裝 → shell out 升 high；配件缺失 → 誠實 fallback、不爆。對齊 deadcode.py「一個誠實 UNKNOWN 比自信錯誤有用」。

## 二、技術選型

| 用途 | 選型 | 備註 |

## 五、風險與緩解

| 風險 | 緩解 |
|---|---|
| Kotlin/Lua tree-sitter binding 弱/停更 | `@kreuzberg/tree-sitter-language-pack` 備援（306+ 語言）|
| better-sqlite3 native 編譯影響「零編譯」分發 | 評估 `node:sqlite`(Node22+ 內建) / sql.js(WASM)；或 better-sqlite3 prebuild（多平台有）|
| web-tree-sitter WASM 比 native 慢（掃大 repo）| 先 WASM（分發優先），效能瓶頸再切 native binding（介面相容）|
| 275 測試平移工作量 | 逐階段平移、黃金測試對照 Python 版輸出當 ground truth |
| 重寫期既有 Python 版凍結＝空窗 | 既有 Python 版保留可用（不刪）、TS 版逐階段達 parity 才切換 |
| 一次全重寫不可逆/工程巨大 | 每階段黃金測試對照 Python 版（外部 ground truth），未過不進下一階段；CodeSextant 無獨立 git repo→重寫進獨立子目錄、達 parity 再定位 |
